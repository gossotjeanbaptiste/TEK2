# 📋 Issues Guide

Objective: create actionable tickets that are easy to handle.

## 1. Choose the right template

- 🐛 **Bug report**: a broken behavior.
- ✨ **Feature request**: a functional improvement.
- 🧹 **Tech Task**: refactor, technical debt, maintenance.

## 2. Essential fields to fill

### Bug
- Clear summary
- Observed / expected behavior
- Reproduction steps (at least 3)
- Environment (OS, branch/commit)
- Impact (Blocking / Major / Medium / Minor)

### Feature
- User need
- Acceptance criteria (at least 3)
- Scope (included / excluded)
- Test strategy

### Tech Task
- Technical objective
- Context
- Impacted area and risk
- Definition of Done

## 3. Best practices

- One issue = one idea.
- Check at least one relevant Zappy mission.
- Add useful evidence if relevant (screenshot, logs, video).
- Be specific: avoid vague descriptions.

## 4. Labels (applied by maintainer)

- Type: `bug`, `enhancement`, `tech-debt`
- Priority: `Priority: Critical !!`, `Priority: High +`, `Priority: Low -`
- Status: `Status: WIP`, `Status: Awaiting Review`, `Status: Waiting`, `Status: Stale`
- OS: `OS: Linux`, `OS: Mac`, `OS: Windows`

## Quick checklist

- [ ] Clear title
- [ ] Important sections filled
- [ ] Relevant Zappy mission(s) checked
- [ ] Environment specified (if bug)
- [ ] Acceptance criteria (if feature)
- [ ] Definition of Done (if tech task)
